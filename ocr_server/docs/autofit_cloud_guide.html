FastAPI 백엔드: push하면 자동으로 올라갑니다

새 서버(autofit-backend)는 GitHub backend 브랜치를 1분마다 확인해서, 새 커밋이 있으면 알아서 받아 설치하고 재시작합니다. 서버에 접속하거나 누군가에게 부탁할 필요 없이 push만 하면 됩니다. 지금도 backend 브랜치의 최신 코드가 이 방식으로 올라가 있습니다.

한눈에 보기

공개 주소https://211-233-202-118.sslip.io (HTTPS 완료)
배포 상태 확인https://211-233-202-118.sslip.io/deploy-status ← 지금 올라간 버전, 성공/실패, 실패 이유
헬스 체크https://211-233-202-118.sslip.io/health
API 문서https://211-233-202-118.sslip.io/docs
배포 방법backend 브랜치에 push → 1~2분 안에 자동 반영
실패하면이전 버전으로 자동으로 되돌림. 서비스는 멈추지 않음
DB · 로그인Supabase 그대로 사용 (서버에 DB 없음)
OCR 연동설정 완료 (HEALTH_DOCUMENT_OCR_URL, 토큰 입력됨, 모의 모드 꺼짐)

어떻게 동작하나요?

  1. pushbackend 브랜치에 커밋을 올린다
  2. 확인서버가 1분마다 새 커밋이 있는지 본다
  3. 설치코드를 받고, requirements.txt가 바뀌었으면 라이브러리도 설치
  4. 재시작앱을 다시 켜고 /health가 응답하는지 30초간 확인
  5. 결과성공이면 새 버전 운영. 실패면 이전 버전으로 되돌리고 실패 이유를 상태 페이지에 기록

실행 명령은 Render와 같은 uvicorn backend.app.main:app입니다(서버 안에서 2개 프로세스). HTTPS 인증서, 재부팅 후 자동 시작, 프로그램이 죽었을 때 3초 뒤 재시작도 서버가 처리합니다.

처음 한 번: 비밀값 전달

백엔드 담당이승현

비밀값은 GitHub에 올리면 안 되므로 자동 배포로 넣을 수 없습니다. 아래 값을 이승현에게 개인 메시지로 한 번만 보내 주세요. 서버에 넣으면 1분 안에 자동으로 적용됩니다.

이름넣을 값비밀?
SUPABASE_URL, SUPABASE_PUBLISHABLE_KEY, SUPABASE_SERVICE_ROLE_KEYRender에 넣어 둔 값과 같게비밀
FRONTEND_ORIGIN프론트엔드 주소. 이 주소에서 오는 요청만 허용됩니다(CORS). 끝에 /를 붙이지 않습니다
CHAT_AI_ENABLED, CHAT_AI_URL, CHAT_AI_API_KEYAI 서버(이병희) 연동을 켤 때만. Render와 같게키는 비밀
ENABLE_TEST_ENDPOINTS, API_DOCS_ENABLED, MAX_REQUEST_BODY_BYTESRender와 다르게 하고 싶을 때만. 지금은 기본값(테스트 API·문서 켜짐, 업로드 12MB)

이미 넣어 둔 값: BACKEND_ALLOWED_HOSTS(새 주소 포함), HEALTH_DOCUMENT_OCR_URL·_TOKEN, HEALTH_DOCUMENT_OCR_MOCK_ENABLED=false, API_DOCS_ENABLED=true. 적용이 끝나면 상태 페이지의 missing_settings가 빈 목록 []이 됩니다.

매번: push하고 확인하기

백엔드 담당
  1. 평소처럼 backend 브랜치에 push합니다.
  2. 1~2분 뒤 https://211-233-202-118.sslip.io/deploy-status를 엽니다.
  3. "result": "success"이고 running_commit이 방금 올린 커밋 번호(앞 7자리)이면 끝입니다.

예시 (지금 서버의 실제 상태):

{
  "branch": "backend",
  "result": "success",
  "running_commit": "9668c33",
  "running_message": "fix(health): require review for suspicious OCR values",
  "running_since": "2026-09-23T16:50:51+09:00",
  "last_checked": "2026-09-23T16:51:54+09:00",
  "failed_commit": null,
  "failed_message": null,
  "error": null,
  "missing_settings": ["SUPABASE_URL", "SUPABASE_PUBLISHABLE_KEY", "SUPABASE_SERVICE_ROLE_KEY", "FRONTEND_ORIGIN"]
}

상태 페이지 읽는 법

항목 / 값뜻할 일
result: success마지막 배포 성공, 정상 운영 중없음
result: failed_rolled_back새 커밋이 켜지지 않아 이전 버전으로 되돌림. 서비스는 이전 버전으로 정상 동작 중error를 보고 고쳐서 다시 push하면 자동 재시도
result: not_running앱이 켜지지 않음 (주로 설정값 문제)이승현에게 알리기
running_commit지금 서버에서 돌고 있는 커밋
failed_commit · error실패한 커밋과 원인 한 줄 (예: ModuleNotFoundError: …)같은 커밋은 다시 시도하지 않으니 새 커밋으로 고치기
missing_settings아직 안 넣은 필수 설정 이름비어 있지 않으면 해당 기능(로그인·DB)이 동작하지 않음
last_checked서버가 GitHub를 마지막으로 확인한 시각몇 분째 그대로면 이승현에게 알리기

상태 페이지는 누구나 볼 수 있어서 비밀값은 표시하지 않습니다. 오류 문장에 설정값이 섞여 있으면 ***로 가려집니다.

문제가 생기면

증상뜻해결
push했는데 반영이 안 됨아직 1분 확인 주기 전이거나 배포 실패2분 뒤 상태 페이지의 result·error 확인
failed_rolled_back새 코드가 켜지다 오류 (import 오류, 문법 오류, 빠진 라이브러리 등)error 문장대로 고쳐 새 커밋 push. 로컬에서 uvicorn backend.app.main:app으로 먼저 켜 보면 확실
로그인·DB 기능만 500 오류Supabase 값이 아직 없음상태 페이지 missing_settings 확인 → 이승현에게 값 전달
400 Invalid host header허용되지 않은 주소로 접속새 주소를 쓰는지 확인. 다른 주소를 쓰려면 이승현에게
브라우저 CORS 오류FRONTEND_ORIGIN이 실제 프론트 주소와 다름정확한 주소(끝의 / 없이)를 이승현에게 전달

서버 로그를 직접 봐야 할 때는 이승현에게 요청하거나, SSH 공개 키와 접속 장소의 인터넷 주소를 보내 주면 접속 계정을 만들어 드립니다.

주의할 것

  • backend 브랜치에 push하면 1~2분 안에 서버에 바로 반영됩니다. 켜지지 않는 코드는 자동으로 되돌리지만, 켜지기는 하는데 기능이 틀린 코드는 그대로 올라갑니다. 로컬에서 확인한 뒤 push해 주세요.
  • 실행 명령(backend.app.main:app)이나 폴더 구조를 바꾸거나, 시작 전에 해야 할 일(예: DB 마이그레이션)이 생기면 이승현에게 먼저 알려 주세요. 자동 배포 설정도 함께 바꿔야 합니다.
  • Supabase Service Role Key 등 비밀값을 GitHub·단체 채팅에 올리지 마세요.
  • 설정 파일 규칙: 값이 없는 항목을 KEY=처럼 비워 두면 앱이 시작하지 못합니다(이승현이 관리).
