# 챗봇 답변 분기 1차

2026-09-08 로컬 구현. 이번 변경은 GitHub 업로드·Render 배포·DB 변경을 하지 않았다.
팀원 모델은 아직 호출하지 않는다. 기존 점수 및 식사·운동 기록 요약 범위에 적용한다.

## 분기 우선순위

| 내부 route | 조건 | 처리 | 질문 예시 |
|---|---|---|---|
| clarification | 질문 모호·미지원 | 범위 재질문 | 운동 기록 보여줘 |
| need_more_data | DB 근거 부족 | 부족 정보 안내 | 점수 하락 이유는? |
| ai_required | 근거 있는 설명 요청 | 모델 연결 대기 | 이번 주 운동 기록 설명해줘 |
| database | DB만으로 답변 가능 | 기록 요약 반환 | 이번 주 운동 몇 번 했어? |

1. 질문 주제와 지원 범위를 확인한다. 기간 누락, 복합 질문, 미지원 요청은 임의로 해석하지 않는다.
2. 지원 범위라면 기존의 로그인 사용자 전용 조회 함수를 실행한다.
3. 기록·영양 정보·비교 평가·원인 근거 등이 부족하면 추가 정보 안내로 종료한다.
4. DB 근거가 충분한 기록 설명·해석 요청만 AI 필요로 분류한다.
5. 나머지는 DB 답변을 반환한다. DB 장애는 기존 오류로 반환하며 AI로 우회하지 않는다.

점수 두 개만으로 점수 하락 원인을 설명할 수 없으므로 AI 대상이 아니다.
현재 점수 설명에 필요한 평가 항목별 근거 조회는 미구현이며 `assessment_explanation_evidence`를 안내한다.
식사·운동 추천, 진단, 타인 정보, 데이터 수정, 미지원 기간 및 주제는 AI로 자동 전달하지 않는다.
분류는 한국어 키워드 기반이며 모든 자연어 표현이나 후속 대화 문맥을 이해하는 기능은 아니다.

## 현재 응답과 모델 연결 지점

`backend/app/chat_answers.py`의 `decide_answer()`가 `AnswerDecision(route, answer)`를 반환한다.
`answer_question()`은 이 결정을 받아 기존 API 응답 형식으로 반환한다.
미리보기와 메시지 저장 모두 기존의 `answer_question()` 호출을 이용한다.

`ai_required`는 **내부 연결 대상 표시**이며 실제 AI 응답이라는 뜻이 아니다.
현재는 검증된 DB 요약에 AI 미연결 안내만 덧붙인다. 따라서 실제 `response_source`는
`database`로 유지하고 `needs_more_data`는 false다. 사용자에게 없는 데이터를 추가 입력하라고 요구하지 않는다.
route 필드는 클라이언트 응답이나 DB 컬럼에 추가하지 않았다. 외래키 및 DB 변경도 없다.

모델 연결 시에는 `ai_required` 처리 지점에서만 호출하도록 확장한다.
모델 입력·출력 검증, 최소한의 근거 전달, 타임아웃 및 실패 처리와 응답 출처 표시는 별도 구현 대상이다.

## 검증

새 분기·API 검사 15개와 기존 검사를 포함해 Python 전체 185개 통과.
검사 범위: 조회 후 분기, 근거 부족 우선, 미지원 요청 차단, 점수 원인 추측 방지,
모델 미연결 안내, DB 오류 전파, 기존 API 형식 및 로그인 사용자 조회 유지.
공용 서버 및 프론트 화면에서는 아직 이번 변경을 검증하지 않았다.
