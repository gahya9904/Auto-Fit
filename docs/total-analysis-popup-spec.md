# 종합 분석 팝업 설계 및 계산 명세

작성일: 2026-09-17 · 버전: 1.0 · 범위: 첨부 화면 3개 · 상태: 개발 인계용 설계

이 문서는 화면에 이미 보이는 구성과 저장 구조를 조사하고, 누락된 동작·계산·판정·출처 규칙을 보완한다. 런타임 코드, API, DB 변경은 포함하지 않는다. 첨부 이미지의 문구와 숫자는 검토 대상이며 검증된 기준으로 간주하지 않는다.

## 1. 기존 설계 확인 결과

확인 범위는 현재 작업 폴더의 `docs`, `backend/app`, `backend/tests`, `supabase/migrations`, `g.html`, `README.md`이다. 별도 Figma 파일이나 외부 기획 문서는 이번 요청에 제공되지 않았으므로 그 존재 여부는 확인하지 않았다.

| 팝업 | 확인된 부분 | 누락된 부분 | 결론 |
|---|---|---|---|
| 체성분 관련 추가 지표 | 이미지에 BMI·체중·체지방량 카드와 해석 요약 존재. 수치 저장 필드 존재 | 수치 선택, 파생 계산, 배지, 요약 분기, 누락·오류 규칙 | 시각 구성이 있으며 기능·수식 설계 보완 필요 |
| 체지방률 판정 기준 | 이미지에 현재 수치·판정·범위·출처 버튼 존재. 평가 항목 저장 필드 존재 | 실제 적용 기준 ID·버전, 성별·연령 적용 조건, 경계값·출처 연결 | 판정 근거를 재현하는 설계 보완 필요 |
| 건강검진 관련 공식 기준 | 이미지에 기관·자료·연도·활용 항목·원문 버튼 존재 | 실재 자료 식별, 발행/개정일, 적용 항목 연결, 원문 URL | 출처 데이터 및 연결 설계 보완 필요 |

확인 근거:

- `backend/app/health_documents.py`: `BodyCompositionData`, `HealthCheckupData`에 키·체중·BMI·체지방량·체지방률·골격근량·공복혈당·혈압 입력 필드가 있다. 확인한 입력/확정 경로에는 이 팝업의 파생 수식이나 기준 선택기가 없다.
- `supabase/migrations/20260901055003_remote_schema.sql`: `body_compositions`, `health_checkups`에 측정 수치가 있고, `health_assessment_items`에 `metric_value`, `evaluation_status`, `evaluation`이 있다. `health_assessments`의 `input_snapshot`, `raw_result`, `model_version`은 적용 기준 스냅샷 보존에 활용 가능하다. 기준 전용 레지스트리는 확인되지 않았다.
- `backend/app/chat_health_scores.py`: 기존 평가 점수·항목을 조회해서 설명한다. 체지방률 판정을 새로 계산하는 기능은 아니다.
- 현재 OpenAPI·화면 연동 문서에서 이 세 팝업의 전용 계약은 확인되지 않았다. 아래 API는 신규 제안이며 기존 API로 호출하면 안 된다.

## 2. 공통 UI 및 데이터 규칙

세 화면은 바텀시트로 구성한다. 화면을 가리는 배경, 상단 핸들, 제목·설명, 우측 닫기, 본문 순서를 유지한다. 최대 높이는 안전 영역을 제외한 화면 높이의 90%, 초과 본문은 내부 스크롤한다. 배경 스크롤을 잠그고 X·배경 탭·Escape·아래로 닫기 제스처로 종료한다. 핸들 제스처를 지원하지 않는 환경에서도 X로 닫을 수 있어야 한다.

`dialog`와 `aria-modal`을 적용하고 제목을 연결한다. 열 때 제목 또는 첫 조작 요소로 포커스를 옮기고 포커스를 시트 안에 유지한다. 닫으면 진입 버튼으로 복귀한다. 닫기 버튼 터치 영역은 44×44 px 이상으로 한다. 상태는 색상과 텍스트를 함께 표시한다.

### 데이터 선택

1. 종합 분석의 `health_assessment_id`를 기준으로 연결된 `body_composition_id`, `health_checkup_id`와 평가 당시 스냅샷을 사용한다. 팝업을 열 때 최신 수치로 바꿔 과거 분석과 혼합하지 않는다.
2. 평가가 없는 미리보기에서는 사용자 확인을 마친 체성분 기록 한 건을 사용한다. `measured_at <= 조회 시점` 중 최신, 동률이면 `created_at`, ID 내림차순으로 정한다. 서로 다른 날짜의 키·체중·지방량을 합쳐 계산하지 않는다.
3. 검진 수치와 체성분 수치는 별도 기록을 유지한다. 카드 또는 시트에 각각의 측정일을 표시하고, 다른 날짜인 경우 차이를 알린다.
4. `null`은 0이 아니다. 값이 없으면 `—`와 `측정값 없음`, 기준이 없으면 `판정 보류`, 입력 충돌이면 `확인 필요`를 사용한다. 미확인 OCR 값을 판정에 사용하지 않는다.
5. 성인 기본 기준의 제품 적용 범위는 만 19세 이상, 임신 등 별도 기준이 필요한 조건이 없다고 확인된 경우다. 이 적용 범위는 제품 정책이며 출처의 발행 사실이 아니다. 조건 미확인 또는 범위 외에는 일반 기준 판정을 보류한다. 원문 자체가 더 좁은 대상 조건을 명시하면 그 조건을 우선한다.
6. 연령은 측정일의 만 나이로 계산한다. `측정연도 - 출생연도 - (그해 생일 전이면 1)`. 성별·연령을 사용하는 기준에서 정보가 없으면 추정하지 않는다. 현재 프로필과 당시 정보가 다르면 평가 스냅샷을 우선한다.

### 로딩·빈 화면·실패

| 상태 | 표시 및 동작 |
|---|---|
| 조회 중 | 제목·닫기는 사용 가능, 본문 스켈레톤, 예시 숫자 숨김 |
| 데이터 없음 | 측정값 없음 안내, 기존 건강자료 입력 흐름으로 이동 버튼 |
| 일부 값 없음 | 있는 값만 표시, 누락 카드와 요약은 누락 상태 표시 |
| 조회 실패 | 오류 안내·재시도, 이전 성공 데이터를 현재 결과로 표시하지 않음 |
| 과거 결과의 기준 누락 | 수치는 유지, 판정 보류·기준 정보 없음; 최신 기준으로 조용히 덮어쓰지 않음 |
| 출처 메타데이터 없음 | 출처 확인 중, 원문 버튼 비활성 |
| 원문 링크 실패 | 출처 정보는 유지, 열기 실패 안내·재시도 |

## 3. 팝업 A — 체성분 관련 추가 지표

진입: 종합 분석의 `체성분 관련 추가 지표 보기` 버튼. 순서: 제목·설명 → 측정일 → BMI → 체중 → 체지방량 → 해석 요약 → 하단 안내.

| 구성 | 표시 규칙 | 문구 |
|---|---|---|
| BMI | 소수 1자리, kg/m². 계산 출처 또는 측정기 보고값 표시 | 정상일 때 `BMI는 정상 범위예요. 체지방률과 근육량도 함께 확인해요.` |
| 체중 | 소수 1자리 kg, 정상/높음 배지 없음 | `체중만으로 체성분 상태를 충분히 설명하기 어려워요.` |
| 체지방량 | 소수 1자리 kg. 추정 계산일 때 `계산값` 표시 | 지방량 자체의 절대 kg로 정상/높음 판정하지 않음 |
| 지방량 카드 배지 | 같은 기록의 체지방률 판정을 보조 표시하려면 `체지방률 높음`처럼 지표를 명시 | 화면의 단순 `높음`은 수정 |
| 하단 | 보조 지표임을 설명 | `현재 분석에서 함께 확인한 체성분 지표예요.` |

### 계산 수식

기호: `W` = 체중 kg, `H` = 키 cm, `F` = 체지방량 kg, `P` = 체지방률 %. 모든 연산은 Decimal로 수행한다.

```text
h = H / 100
BMI_calc = W / h²                         (W > 0, H > 0)
F_calc = W × P / 100                     (W > 0, 0 ≤ P ≤ 100)
P_calc = F / W × 100                     (W > 0, 0 ≤ F ≤ W)
제지방량 = W - F                          (참고용, 골격근량으로 대체 불가)
표시(x) = Decimal ROUND_HALF_UP(x, 소수 1자리)
```

값 선택: 같은 확인 기록의 직접 측정/보고값 우선 → 직접 값이 없을 때만 수식으로 보완 → 둘 다 없으면 누락. BMI 보고값과 계산값은 각각 보존한다. 보고된 BMI를 우선 표시·판정하되 같은 기록의 검증 가능한 키·체중이 있으면 충돌을 확인한다. 원본 저장값을 계산값으로 덮어쓰지 않는다.

직접 보고된 `F`, `P`, `BMI`와 계산값의 표시 결과가 다르면 `discrepancy` 정보를 반환한다. **표시 차이는 확인 안내이며 자동으로 측정 오류라고 단정하지 않는다.** 단, `F > W`, 골격근량 > 체중, 범위 밖 비율, 0 이하 키·체중처럼 물리적/계산적 모순이면 관련 지표와 요약의 판정을 보류한다. 직접값끼리 서로 다른 상태 구간을 만들면 확인 필요 상태로 처리한다.

### BMI 판정

성인 한국 기준 참고값 [S1]. 원시 유효값으로 판정하고 소수 1자리 표시는 별도로 한다.

| 조건 | 상태 코드 | 표시 |
|---|---|---|
| BMI < 18.5 | low | 저체중 |
| 18.5 ≤ BMI < 23 | normal | 정상 |
| 23 ≤ BMI < 25 | caution | 과체중 |
| BMI ≥ 25 | high | 비만 범위 |

범위 라벨은 `18.5 이상 ~ 23 미만`처럼 부등호로 표시한다. `22.9 이하`를 코드 조건으로 사용하면 22.95가 빠질 수 있다. 22.95는 정상인데 반올림 표시가 23.0일 수 있으므로 경계 근처에서는 `판정에 사용한 값 22.95`를 추가한다.

### 해석 요약 분기

아래 문구는 제품 설명 규칙이며 공식 진단이나 운동·식단 처방이 아니다. 점수나 감량 전략을 새로 계산하지 않는다.

| 우선순위·조건 | 요약 |
|---|---|
| 1. 수치 모순 또는 기준 충돌 | `입력값과 적용 기준을 확인한 후 해석할 수 있어요.` |
| 2. BMI 정상 + 체지방률 높음 + 근육량 낮음 모두 근거 있음 | `BMI는 정상 범위지만 체지방률은 높고 골격근량은 낮게 평가됐어요. 체중과 함께 체성분을 확인해요.` |
| 3. BMI 정상 + 체지방률 높음, 근육 판정 없음 | `BMI는 정상 범위지만 체지방률은 높게 평가됐어요. 골격근량은 적용 기준 확인이 필요해요.` |
| 4. BMI·체지방률 정상, 근육량 정상 | `확인된 체성분 지표는 적용 기준의 정상 범위예요.` |
| 5. 하나 이상 낮음/주의/높음 | `정상 범위를 벗어난 지표가 있어요. 각 지표의 기준을 함께 확인해요.` |
| 6. 판정 자료 불충분 | `현재 자료만으로 체성분을 충분히 해석하기 어려워요.` |

원래 이미지의 `체중 감소보다 체성분 개선이 더 중요한 상태`는 전략 판단 근거가 있을 때만 사용한다. 사용할 경우 기존 전략 엔진의 결정·버전·근거 ID를 별도로 전달해야 하며 이 팝업에서 BMI만으로 결정하지 않는다.

## 4. 팝업 B — 체지방률 판정 기준

진입: 체지방률 항목의 `기준 자세히 보기`. 순서: 제목·설명 → 현재 수치/판정 → 적용 기준 이름·대상 → 실제 판정 범위 → 참고 출처 보기.

시트와 배경 카드의 수치·상태·기준 버전은 동일해야 한다. 선택된 한 범위에만 `현재 수치` 표시를 붙인다. 실제 판정에 사용하지 않은 예시 표는 기본 화면에서 제거한다. 유지해야 한다면 `예시 · 현재 판정에는 미적용`이라고 구분한다.

### 기준 선택 순서

1. 확인된 측정기관/기기의 해당 기록 판정과 기준 범위가 있으면 원문 그대로 사용한다. 판정만 있고 범위가 없으면 `측정기관 판정`, `범위 정보 미제공`을 표시한다. 범위를 역으로 만들어내지 않는다.
2. 기관 판정이 없고 **확인된 InBody 기록**이며 대상 조건에 맞으면 제조사 공개 참고 범위 [S2]를 사용한다. 다른 기기에 자동 적용하지 않는다.
3. 그 외에는 수치만 표시하고 `판정 보류 · 적용 가능한 기준이 없어요`를 반환한다.

공개된 제조사 참고 범위는 남성 10~20%, 여성 18~28%이다 [S2]. 문서의 범위 양끝을 포함하도록 다음과 같이 제품 규칙을 명시한다. 이는 해당 참고 범위를 앱 상태로 매핑한 설계다. 연령별 보정은 이 출처에서 확인하지 못했으므로 적용하지 않는다.

```text
(L, U) = 남성 (10, 20), 여성 (18, 28)
classify_pbf(P):
  값 누락/조건 미충족/미지원 기준 → unknown
  범위 밖/입력 충돌 → review_required
  P < L → low
  L ≤ P ≤ U → normal
  P > U → high
```

`low`는 낮음, `normal`은 정상, `high`는 높음이며 배지에 `제조사 참고 범위`라는 기준 유형을 함께 보여준다. 이 출처에는 별도의 `주의` 구간이 없으므로 제조사 기준에 임의로 추가하지 않는다.

### 스크린샷 구간 처리

이미지의 `정상 18.0~27.9 / 주의 28.0~31.9 / 높음 32.0 이상` 전체 구간을 뒷받침하는 출처는 이번 조사에서 확인하지 못했다. 여성 참고 범위와 일부 숫자가 비슷해도 서로 같은 기준은 아니다. 배포 기준으로 채택하지 않는다.

디자인 예시가 필요하면 아래 **미적용 샘플**만 사용할 수 있다:

```text
P < 18       → 낮음
18 ≤ P < 28  → 정상
28 ≤ P < 32  → 주의
P ≥ 32       → 높음
```

이 샘플은 `demo_only=true`이며 사용자 분석·요약·전략에는 사용하지 않는다. 승인된 근거·대상·버전이 등록되기 전까지 서비스 기본값으로 활성화하지 않는다. 제조사 참고 범위에서는 여성의 정확히 28%가 정상이라는 점도 이 샘플과 다르다.

### 골격근량 기준 재사용

배경 화면의 골격근량 `기준 자세히 보기`도 이 시트 구조를 재사용한다. `골격근량 21 kg`만으로 낮다고 판정하지 않는다.

같은 측정 기록에서 제공된 골격근량 참고 하한 `S_L`, 상한 `S_U`가 있다면 `S < S_L → 낮음`, `S_L ≤ S ≤ S_U → 정상`, `S > S_U → 높음`으로 판정한다. 범위의 포함 조건이 원문에 따로 있으면 원문을 따른다. 범위가 없고 기관 판정만 있으면 기관 판정만 인용한다. 둘 다 없으면 판정 보류다. 임의의 체중 비율이나 `전체 골격근량/키²`를 임상 근감소증 기준에 대입하지 않는다.

## 5. 팝업 C — 건강검진 관련 기준 출처

진입: 분석 기준 섹션의 출처 버튼 또는 기준 팝업의 `참고 출처 보기`. 화면 제목은 선택된 출처에 맞춘다. 정부 출처는 `건강검진 관련 공식 정보`, 제조사 출처는 `체성분 관련 제조사 참고 기준`으로 표시한다.

| 화면 항목 | 데이터·표시 규칙 |
|---|---|
| 기관 | 실제 발행 기관명. `국가건강검진 관련 공식 기준`은 기관명이 아니므로 대체 |
| 자료명 | 원문 제목 그대로. 확인되지 않은 `건강검진 결과 해석 가이드` 사용 금지 |
| 발행·개정 | 원문에 확인되는 날짜만 표시. 없으면 `발행·개정일 미확인` |
| 출처 확인일 | `2026-09-17`을 별도 표시. 확인 연도를 개정 연도로 사용하지 않음 |
| 활용 항목 | **이번 분석에 실제 적용된** metric 목록. 출처에 없는 항목 태그 금지 |
| 이 분석에 적용된 부분 | metric·적용 조건·기준 내용. 복수 출처면 출처별 카드로 구분 |
| 원문 확인 | 선택한 출처의 실제 HTTPS 페이지로 이동. 원문을 찾아볼 수 없으면 비활성 |

예: 공복혈당은 질병관리청 `당뇨병` [S3], 혈압은 질병관리청 `고혈압` [S4]를 별도 카드로 표시한다. 한 문서가 모든 지표의 근거인 것처럼 합치지 않는다. 이번 결과에서 혈압을 사용하지 않았으면 혈압 태그를 표시하지 않는다. 외부 페이지를 연 후 돌아오면 기존 시트·스크롤을 복원한다.

### 검진 판정 수식

공복혈당 `G`의 단위는 mg/dL이며 공복 검사가 확인되어야 한다. 측정법·단위·공복 여부가 불명확하면 판정을 보류한다. 아래 구간은 공복혈당의 고혈당 선별 분류 [S3]다. `100 미만`이 다른 모든 건강 상태까지 정상임을 뜻하지 않는다. 기관이 저혈당 등 별도 이상을 표시한 기록은 그 표시를 유지하고 자동 정상으로 덮어쓰지 않는다.

```text
G < 100         → normal  / 공복혈당 정상 범위
100 ≤ G < 126   → caution / 공복혈당장애 범위
G ≥ 126         → high    / 당뇨병 의심 범위
```

108 mg/dL은 `주의 · 공복혈당장애 범위`다. 단일 수치로 확정 진단 문구를 만들지 않는다.

혈압 `SBP`, `DBP`의 단위는 mmHg이며 둘 다 확인되어야 한다. 아래는 공개된 정상·고혈압 경계를 앱의 3개 표시 상태로 묶은 규칙 [S4]이며 중간 상태는 제품 표시 용어다.

```text
SBP ≥ 140 또는 DBP ≥ 90          → high / 고혈압 범위
SBP < 120 그리고 DBP < 80        → normal / 정상혈압 범위
그 외                            → caution / 정상혈압 기준 초과
```

기관이 낮은 혈압 등 이상을 표시한 경우 이를 유지한다. 측정값에 모순이 있거나 SBP/DBP 중 하나만 있으면 판정 보류다. 한 번의 혈압 결과로 고혈압 확정 진단을 생성하지 않는다. 임상 세부 단계나 치료 목표는 이 3단계 표시와 구분한다.

## 6. 프론트·백엔드 연결 제안

신규 제안: `GET /api/health-assessments/{assessment_id}/popups`. 인증된 본인 평가만 조회하고 다른 사용자 평가에는 404를 반환한다. 서버가 계산·판정·기준 선택을 담당하며 프론트에서 임계값을 재계산하지 않는다. 토큰·service role 키·원본 건강 문서 전체는 응답에 포함하지 않는다. 원문 링크는 등록된 출처 URL만 사용한다.

최소 응답 계약:

| 필드 | 타입 | 의미 |
|---|---|---|
| assessment_id | UUID | 배경 분석과 동일한 평가 |
| calculation_version | string | 수식·문구 분기 버전 |
| body_composition_id / health_checkup_id | UUID 또는 null | 원본 기록 연결 |
| metrics[] | array | 아래 공통 지표 구조 |
| interpretation | object | `rule_id, text, evidence_metric_keys[]` |
| sources[] | array | 이번 분석에 실제 적용된 출처 |

`metrics[]` 공통 구조:

```json
{
  "key": "body_fat_percentage",
  "raw_value": "32.0",
  "display_value": "32.0",
  "unit": "%",
  "value_origin": "reported",
  "measured_at": "2026-09-17T09:00:00+09:00",
  "status": "high",
  "status_label": "높음",
  "criteria_id": "inbody-public-pbf-adult-female",
  "criteria_version": "verified-2026-09-17",
  "criteria_type": "manufacturer_reference",
  "source_ids": ["S2"],
  "applied_conditions": {"sex": "female", "adult_eligibility_confirmed": true},
  "ranges": [
    {"status": "low", "min": "0", "min_inclusive": true, "max": "18", "max_inclusive": false},
    {"status": "normal", "min": "18", "min_inclusive": true, "max": "28", "max_inclusive": true},
    {"status": "high", "min": "28", "min_inclusive": false, "max": "100", "max_inclusive": true}
  ],
  "missing_fields": [],
  "discrepancy": null
}
```

위 JSON은 **확인된 InBody 기록이며 대상 조건이 일치할 때만 사용하는 예시**다. 첨부 화면 사용자의 속성을 추정한 것이 아니다. `criteria_version`은 앱의 확인 버전이며 원문의 개정일이 아니다. `value_origin`은 `reported / calculated`, 상태는 `low / normal / caution / high / unknown / review_required`를 사용한다. 수치는 정밀도를 보존하는 십진 문자열 또는 null로 반환한다.

출처 구조: `source_id, publisher, title, url, published_at?, revised_at?, verified_at, source_type, applied_metric_keys[], applied_excerpt_summary`. 원문 발행일이 미확인이면 null로 둔다. 개인 측정지는 `measurement_report`로 구분하며 공개 페이지가 없으면 원문 URL은 null로 둔다.

기준 등록 구조: `criteria_id, version, metric_key, unit, source_ids[], applicable_conditions, ranges[], enabled`. 등록 시 구간 중복과 누락을 검증한다. 예시 구간은 `enabled=false`로 둔다.

평가 시 기준·조건·원본 수치·계산 결과·출처 버전·해석 rule_id를 스냅샷에 저장한다. 기존 `input_snapshot`, `raw_result`를 활용하는 제안이며 이번 작업에서 DB를 변경하지 않는다. 과거 평가에 이 정보가 없으면 수치는 표시하고 기준 정보 없음으로 안내한다. 새 기준으로 재평가한다면 별도 평가로 처리한다.

## 7. 계산 예시 및 수용 기준

### 첨부 화면 수치 검증

```text
체지방량: 68.4 × 32.0 / 100 = 21.888 kg → 21.9 kg
역산: 21.9 / 68.4 × 100 = 32.017543... % → 32.0 %
BMI 22.3·체중 68.4의 관계에서 역산한 키:
  sqrt(68.4 / 22.3) × 100 ≈ 175.1361 cm
```

위 키는 수학적 정합성 확인용이며 실제 입력값으로 보완하지 않는다. BMI 계산 재현에는 측정된 키가 필요하다. 직접 보고된 BMI 22.3은 표시할 수 있다. 골격근량 21 kg이 낮은지는 이 이미지만으로 판정할 수 없다.

| ID | 条件 | 期待結果 |
|---|---|---|
| QA-01 | W=68.4, P=32, F 없음 | 계산값 21.9 kg, 계산값 표시 |
| QA-02 | H=175.14, W=68.4, BMI 없음 | BMI 약 22.2990, 표시 22.3, 정상 |
| QA-03 | BMI=18.49 / 18.5 / 22.95 / 23 / 25 | 저체중 / 정상 / 정상＋원시값 표시 / 과체중 / 비만 범위 |

| QA-05 | InBody 남성 조건 일치, P=10 / 20 / 20.01 | 정상 / 정상 / 높음 |
| QA-06 | 기준이 성별을 요구하나 성별 불명 | 값 표시, 판정 보류, 추정 없음 |
| QA-07 | 골격근량 21 kg, 참고 범위·기관 판정 없음 | 낮음 단정 금지, 판정 보류 |
