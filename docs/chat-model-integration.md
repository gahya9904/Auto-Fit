# 챗봇 모델 연결 계약

2026-09-08 로컬 구현. 실제 모델 호출·배포는 아직 하지 않았으며 기본 비활성이다.
검토한 AI 브랜치: `origin/ai`, `65be2bd0d78a84731bf0e85dacba955041f640f5`.
로컬 `ai` 작업 폴더에서 챗봇 경로를 README와 동일한 `/ai/chat`으로 수정했다.
원격 푸시·병합·배포는 하지 않았다. 양쪽 변경을 함께 배포해야 한다.

## 현재 연결 범위

1. 로그인 사용자의 DB 기록을 기존 방식으로 조회한다.
2. 지원되는 식사·운동 기록 요약에 설명을 요청했고 근거가 충분할 때만 AI를 호출한다.
3. 성공하면 기존 응답의 `content`만 모델 설명으로 바꾸고 `response_source=database_ai`로 반환한다.
4. DB의 `evidence`, `intent`, `required_data`, `needs_more_data`는 유지한다.
5. 비활성·모델 오류·잘못된 응답이면 `database` 요약과 AI 설명 불가 안내를 반환한다.

DB 장애는 기존 오류를 유지한다. 데이터 부족은 `need_more_data`, 미지원 질문은 재질문으로
처리하며 AI를 호출하지 않는다. 일반 상담, 추천, 건강 점수 원인 분석, 이전 대화를 사용하는
후속 질문까지 지원하는 것은 아니다. 예시: `이번 주 운동 기록 설명해줘`.

## 백엔드 → AI 서버

| 항목 | 규격 | 설명 |
|---|---|---|
| 경로 | `POST /ai/chat` | README와 통일 |
| 인증 | `Authorization: Bearer <공유키>` | 서버 간 인증 |
| `question` | 문자열 | 질문과 집계 근거 |
| `user_info` | `{}` | 현재 미사용 |
| `chat_history` | `[]` | 현재 미사용 |

AI 라우터와 백엔드를 README의 `/ai/chat`으로 통일했다. 기존 `/chat` 직접 호출은 수정해야 한다.
현재 AI 라우터가 `question`만 모델에 전달하므로, 백엔드는 질문과 집계 근거를 JSON으로
직렬화하여 `question`에 포함한다. 향후 구조화 입력을 처리하도록 팀원이 수정하면 함께 변경한다.

응답 예시(비스트리밍):

```json
{"answer":"이번 주 운동이 2회 기록되어 있어요.","model":"사용한 모델명"}
```

`answer`: 공백 제외 1~4000자 문자열. `model`: 1~200자 문자열.
응답 본문은 최대 64KiB, 전체 호출은 최대 10초, 소켓 타임아웃은 8초다.
자동 재시도·리다이렉트는 하지 않는다. 형식 검증은 사실성·의학적 안전성 검증이 아니다.
프론트에는 모델명·상위 서버 오류·인증키를 반환하지 않는다. 답변은 HTML로 실행하지 말고
텍스트로 표시한다. 이 변경으로 프론트의 요청 형식은 바뀌지 않는다.

## 전송 데이터

- 현재 질문 원문과 운동 횟수·분·추정 열량 또는 식사 건수·추정 열량만 보낸다.
- DB의 이름·이메일·사용자 ID·음식명·건강 문서·과거 대화·인증 토큰은 보내지 않는다.
- 사용자가 질문에 직접 적은 개인정보는 질문 원문에 포함될 수 있다. 익명화 보장은 아니다.
- 프롬프트 경계는 보조 수단이다. AI에는 DB 쓰기나 도구 실행 권한을 부여하지 않는다.
- 기존 백엔드 대화 보관 정책은 변경하지 않는다. AI 서버 및 모델 제공자의 로그·보관 정책은
  별도로 확인해야 하며 백엔드의 삭제가 그쪽 저장 데이터까지 삭제하는 것은 아니다.

## 팀원에게 필요한 작업

| 담당 | 작업 | 완료 조건 |
|---|---|---|
| 모델 개발자 | Bearer 키 검증 | 누락·오류 키 401/403 |
| 모델 개발자 | 서버 주소 공유 | HTTPS `/ai/chat` 응답 |
| 모델 개발자 | 환경변수 로딩 | 실행 시 모델 키 인식 |
| 공동 | 경로 변경 배포 | 양쪽 `/ai/chat` 적용 |
| 공동 | 응답 품질 검증 | 근거 없는 수치 없음 |
| 공동 | 데이터 처리 확인 | 외부 전송·보관 합의 |

현재 AI 브랜치에는 서버 간 인증 검증이 없다. 백엔드가 헤더를 보내는 것만으로 보호되지 않는다.
모델 개발자는 공유키를 서버에서 비교하고, 미설정 시 시작을 실패시키며, 요청·응답 본문이나
키를 로그에 남기지 않아야 한다. `.env`를 쓰려면 현재 미사용인 설정 로더도 연결해야 한다.
OpenAI 키는 AI 서버만 보유한다. 공유키는 별도로 발급하며 프론트에 전달하지 않는다.

## 활성화 순서

1. 위 AI 측 작업과 데이터 처리 합의를 완료한다.
2. 통제된 테스트 데이터로 인증 실패·정상 응답·잘못된 응답·지연 시나리오를 확인한다.
3. 백엔드 서버 전용 환경변수를 설정한다.

| 변수 | 설정 |
|---|---|
| `CHAT_AI_ENABLED` | 기본 `false`, 검증 후 `true` |
| `CHAT_AI_URL` | 신뢰하는 HTTPS `/ai/chat` 전체 주소 |
| `CHAT_AI_API_KEY` | 공백 없는 ASCII 공유키 32자 이상 |

주소는 운영자가 지정하며 사용자 입력으로 받지 않는다. 신뢰하는 소유 서버만 등록한다.
활성 설정이 잘못되면 백엔드 시작이 실패한다. 실제 `.env`나 Render 설정은 이번 작업에서
변경하지 않았다. 문제가 생기면 `CHAT_AI_ENABLED=false`로 재시작하여 DB 전용으로 되돌린다.

4. 승인된 백엔드 배포 후 프론트 → 백엔드 → AI 전체 흐름을 검사한다.
5. 저장된 요청의 재전송은 기존 결과를 반환한다. 단, 동시에 도착한 동일 신규 요청은
   DB 저장은 중복 방지되지만 AI 호출은 중복될 수 있다. 활성화 전 예상 비용을 확인한다.

## 검증 상태

로컬 모의 HTTP 테스트로 계약, 데이터 최소화, 기본 비활성, 인증 헤더, 오류·시간 초과·
응답 제한, DB 우선 분기, 미리보기·저장 API를 검증한다. 실제 모델 서버 인증 검증,
실제 답변 품질, 배포 서버 통합 테스트는 별도 미완료 항목이다.
